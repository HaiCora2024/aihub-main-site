# AIHUB: инструкции для агентов

Область действия: весь репозиторий. Команды выполняются из его корня.
Это актуальная точка входа для разработки, а не публичный API агента.

## С чего начать

1. Прочитать `git status --short` и сохранить чужие незакоммиченные изменения.
2. Выбрать руководство по задаче из таблицы ниже.
3. Открыть реальные исходники: документация не заменяет проверку текущего API.
4. Выполнить относящиеся к задаче проверки и сообщить ограничения.

## Правила изменений

- Frontend: React 18, TypeScript, Vite, multipage HTML. Router и PageBuilder не установлены.
- Новые страницы используют `.aihub-theme`, UI-kit и scoped CSS. Не импортировать
  глобальные legacy-стили или CSS каталога для оформления новой страницы.
- Не переносить DesktopScaleFrame и абсолютные 1920px-сцены в новые страницы.
- Сохранять EN/RU, доступные названия, клавиатуру и reduced motion.
- Внутренние URL строить через `import.meta.env.BASE_URL`; публичный API имеет
  отдельный origin. URL `public/foo` публикуется как `BASE_URL + foo`, без `public/`.
- Не копировать меню и логотип. У текущего SiteHeader только режимы `landing` и
  `shop`; расширение для новой страницы описано в гайде, нельзя выдавать её за магазин.
- Магазин сейчас демонстрационный. `createDemoOrder` не отправляет заявку и не принимает оплату.
- Contact API отправляет реальные письма и строки в Sheets. Не использовать его
  для smoke с реальными контактами и не считать сервером заказов.
- Не добавлять секреты в `VITE_*`, браузерный bundle, `public/`, docs или Git.
- Commit, push в `main`, обновление форка и production-изменения выполнять только
  в рамках явного запроса. Push в `main` запускает Pages workflow.

## Проверки

```bash
node scripts/check-agent-paths.mjs
npx tsc --noEmit -p tsconfig.design-system.json
npx tsc --noEmit -p tsconfig.shop.json
npm run build
node scripts/check-agent-paths.mjs --dist dist
git diff --check
```

`npx tsc --noEmit` с корневым tsconfig не проверяет приложение: там только references.
Общий check: `npx tsc --noEmit -p tsconfig.app.json`. На 15.10.2026 известны шесть
старых ошибок в Cases; точный список есть в [QA](docs/design-system-qa.md).
Не скрывать их и не считать список вечным исключением для новых ошибок.

Для нового каталога страницы добавить собственный TS-check или включить его в
существующий: проверки UI-kit и магазина не охватывают произвольные новые файлы.
Браузерные сценарии и внешняя установка Playwright описаны в профильных гайдах.
Матрица: 390, 768, 1199, 1200, 1440, 1920 px; RU/EN; обычное и reduced motion.

## Визуальные проектные скетчи

Для новой сущности планировки, мебели, стенда, интерьера или 3D-черновика перед
первым утверждением требуется независимый субагент, не создававший проверяемую версию,
открывший фактические виды и первичные источники. Сохранить reviewer ID, версии/SHA,
замечания и вердикт.
Новый файл, экспорт или ракурс сами по себе не являются новой сущностью.
Обычные правки той же сущности не требуют повторного ревью, кроме явного запроса
или низкой уверенности автора. Перед добровольным повтором назвать конкретное сомнение.
Старый pass не является новым; его отсутствие после обычной правки не блокирует выдачу.
Авторская проверка и исправление ошибок обязательны, но закрытие замечаний автором
не меняет вердикт reviewer. Разрешена только ограниченная делегация нужного ревью,
не новые изменения проекта, платные запросы или массовая ретроспективная проверка.
Без первого ревью показывать только как непроверенный черновик, если пользователь
не разрешил исключение. Это правило не распространяется автоматически на кодовые
прототипы; утверждение остаётся за пользователем, review не означает готовности к производству.
