# Магазин: страницы товаров, уровни и подписи цен (этап 1)

Дата: 2026-10-23. Статус: на согласовании.
Основа: ветка `feat/shop-price-ranges-eur` (PR HaiCora2024/aihub-main-site#3,
цены в EUR диапазонами). Работа идёт в `feat/shop-product-pages`.

## Цель

Привести магазин к требованиям для витрины услуг:

- стартовая страница магазина показывает карточки услуг: название, краткое
  описание, диапазон «…–…» или «от …» только там, где он обоснован уровнями,
  валюту, пометку нетто + VAT и CTA «Подробнее»;
- каждая карточка ведёт на отдельную страницу товара (PDP);
- ориентировочная цена нигде не выдаётся за гарантированную окончательную,
  тексты не обещают мгновенного оказания услуги;
- данные услуг и уровней редактируются в одном месте.

Приёмка: все карточки ведут на правильные PDP; диапазоны соответствуют данным
уровней; нет ложных обещаний фиксированной цены и мгновенного результата.

## Решения, принятые с заказчиком

| Вопрос | Решение |
| --- | --- |
| Нетто или брутто | Цены нетто, VAT добавляется сверху |
| Что такое пакет | Уровни внутри услуги, у каждого своя цена и состав |
| Источник уровней | Черновик готовит разработчик, заказчик сверяет до выкладки |
| Что идёт в корзину | Выбранный уровень, сервер считает цену по нему |
| Способ PDP | Отдельный HTML на товар, как `cases/` |

## Разбиение на этапы

1. **Этот документ.** PDP, уровни, карточки, подписи и тексты на EN/RU.
   Данные устроены так, что новые языки добавляются без переделки.
2. Локали PL и UA во всём магазине: меню, checkout, юридические страницы,
   письма, валидация `locale` на сервере. Отдельная спецификация.
3. SEO: hreflang, JSON-LD `Service`/`Offer`, sitemap, при необходимости
   пререндер контента PDP. Отдельная спецификация.

Вне этапа 1: оплата, автоматические счета, расчёт VAT, изменение API контакта.

## 1. Данные

### Коммерческий каталог (`backend/contact-api/shared/catalog.json`)

Единственный источник цен для frontend и backend. Поля товара:

```json
{
  "id": 1,
  "slug": "voice-assistant",
  "unit": "setup",
  "name": { "en": "AI Voice Assistant", "ru": "Голосовой AI-ассистент" },
  "packages": [
    { "id": "start", "priceMinor": 180000, "openEnded": false,
      "name": { "en": "Start", "ru": "Старт" } },
    { "id": "pro", "priceMinor": 400000, "openEnded": true,
      "name": { "en": "Pro", "ru": "Про" } }
  ]
}
```

- `priceFromMinor` и `unitPriceMinor` из PR #3 удаляются; диапазон вычисляется:
  от минимального `priceMinor` до максимального, «+» если у максимального
  уровня `openEnded: true`.
- `slug` переезжает из `data.ts` в каталог: он нужен и скрипту проверки PDP.
- `id` уровня — строка `[a-z0-9-]{1,32}`, уникальная внутри товара.
- `currency` остаётся `EUR`; `version` повышается.
- Уровень с `openEnded: true` может быть только самым дорогим.

### Тексты (`src/shop/data.ts`)

Всё, что не цена: описание, категория, а также для PDP:

- `packages[packageId].features`: 3–5 пунктов состава уровня;
- `priceFactors`: 3–4 пункта «что влияет на цену»;
- `timeline`: ориентир сроков («обычно 2–4 недели после согласования объёма»).

Тип строк `Localized = Record<ShopLanguage, string>`; на этапе 2 к
`ShopLanguage` добавятся `pl` и `uk`, и TypeScript покажет все пропуски.
Если у уровня из каталога нет текстов в `data.ts` или наоборот, `data.ts` бросает
ошибку при загрузке (как сейчас при неверном каталоге), а `check-shop-pages`
ловит это до сборки.

### Отображение цены

| Данные | Карточка и шапка PDP | Уровень на PDP |
| --- | --- | --- |
| Несколько уровней | `€900–2,500` или `€2,500–7,500+` | `€900` |
| Один уровень | `€1,500` | `€1,500` |
| Верхний уровень `openEnded` | `…–7,500+` | `от €7,500` |

Под ценой всегда подпись из одного ключа `copy.priceNote`:
«нетто, + VAT · ориентировочно» / «net, + VAT · indicative».

### Корзина и заявка

- `localStorage.aihub_cart`: `[{ id, packageId, qty }]`.
- Старая запись без `packageId` получает самый дешёвый уровень товара;
  неизвестный `packageId` удаляется, как сейчас неизвестный `id`.
- Строка корзины уникальна по паре `id + packageId`. Лимит заявки: 8 строк
  (как в документации сейчас), `qty` 1..99.
- POST `/api/shop/requests`: `items: [{ id, packageId, qty }]`. Если
  `packageId` отсутствует, сервер берёт самый дешёвый уровень (совместимость
  с незакрытыми вкладками). Неизвестный `packageId` даёт `VALIDATION_ERROR`
  с `fields.items = "invalid"`.
- Сервер сохраняет в `items` также `packageId`, имя уровня и `openEnded`.
- Письма: `1 x Голосовой AI-ассистент · Про (от 4000.00 EUR)`; строка итога
  «Ориентировочно, нетто».
- `GET /api/shop/catalog` отдаёт `packages`; `api.ts` проверяет их форму.
- Сохранённые в SQLite старые заявки не мигрируются: их `items` уже содержат
  цену, письма по ним не пересылаются.

## 2. Страница товара и общий код

### Вынос из `Shop.tsx`

- `src/shop/useShopLanguage.ts`: язык из `?lang=`, переключение, `<html lang>`.
- `src/shop/useShopCart.ts`: чтение/запись корзины, синхронизация между
  вкладками, добавление уровня, счётчик.
- `src/shop/CartDrawer.tsx`: текущая панель корзины без визуальных изменений;
  у строки выводится уровень: «Голосовой AI-ассистент · Про».

`Shop.tsx` и новый `ProductPage.tsx` используют эти модули.

### PDP

- Входы: `shop/<slug>.html` для 8 товаров, в `vite.config.ts` по записи на
  каждый. Файл содержит `<meta name="aihub-product" content="<slug>">`,
  собственные `<title>` и `meta description` на EN, и подключает
  `src/shop/product-main.tsx`.
- `product-main.tsx` читает slug из meta и рендерит `ProductPage`.
- `SiteHeader` в режиме `shop`; хлебные крошки: Магазин → категория → услуга.
  Ссылки сохраняют `?lang`.
- Блоки сверху вниз:
  1. иконка, название, описание, диапазон и `priceNote`, строка
     «Окончательную цену и VAT согласует менеджер до договора»;
  2. уровни: название, состав, цена, кнопка «Выбрать и добавить в корзину»;
     после добавления открывается `CartDrawer`;
  3. «Что влияет на цену»;
  4. «Как проходит работа»: обсуждение → предложение → внедрение, `timeline`;
  5. оговорка корзины и CTA «Обсудить с командой» (контактная форма главной).
- Неизвестный или пустой slug: «Услуга не найдена» и ссылка в магазин.
- Компоненты UI-kit, scoped `.shop-*` стили, EN/RU, клавиатура, reduced motion.
  Матрица ширин как у магазина.

### Стартовая страница магазина

- Карточка: категория, иконка, название, описание, цена, `priceNote`,
  CTA «Подробнее» — ссылка `shop/<slug>.html?lang=<lang>` с доступным именем
  «Подробнее: <название>».
- Кнопка «В корзину» с карточки удаляется. Поиск, фильтры, корзина в шапке
  без изменений.
- Hero-иллюстрация использует товары 0, 1, 4 — не меняется.

## 3. Тексты и юридическая часть

- Заголовок магазина «Готовый AI. / Ваш результат.» →
  «AI-решения / под ваш бизнес.»; EN «Ready-made AI. / Made for you.» →
  «AI solutions / built for your business.».
- Описания:
  - рекомендации: без «на 20–30%» →
    «…чтобы помочь увеличить средний чек»;
  - автозаполнение: без «за секунды вместо часов» →
    «…сокращает ручное заполнение»;
  - воркшоп: «Двухчасовая сессия: разбираем процессы и находим, где AI
    может помочь».
- Тексты уровней, факторов цены и сроков не содержат цифр эффекта и слов
  «гарантированно», «мгновенно», «сразу», «за секунды».
- Корзина: строка «Оценка считается по верхней границе диапазона» удаляется;
  итог подписан «Ориентировочно, нетто». То же в checkout и письмах.
- `src/legal/content.ts`, раздел «Оценка и VAT»: суммы каталога указаны
  нетто, без VAT; цена выбранного уровня ориентировочная; окончательная цена
  и налоги сообщаются до договора. `termsVersion` повышается.

### Черновик уровней (сверить с реальными ценами до выкладки)

| Услуга | Уровни, нетто | Ориентир сроков |
| --- | --- | --- |
| Голосовой AI-ассистент | Старт €1,800 · Бизнес €2,800 · Про от €4,000 | 3–6 недель |
| AI-ассистент в чате | Стандарт €1,500 | 2–4 недели |
| Заказы из почты → 1С | Старт €900 · Расширенный €2,500 | 2–5 недель |
| Автозаполнение документов | Старт €300 · Расширенный €900 | 1–3 недели |
| Бот для KPI-отчётов | Старт €300 · Расширенный €900 | 1–3 недели |
| Анализ тональности чатов | Старт €900 · Расширенный €2,500 | 2–4 недели |
| Персональные рекомендации | Старт €2,500 · Бизнес €5,000 · Про от €7,500 | 4–8 недель |
| Воркшоп по внедрению AI | Сессия €400 · Команда €1,850 | по согласованию даты |

Диапазоны совпадают с утверждёнными в PR #3. Состав уровней:

- Старт: один канал или источник, один основной сценарий, базовая настройка.
- Бизнес / Расширенный: несколько сценариев или источников, интеграция с CRM,
  1С или таблицами, отчёты.
- Про: несколько интеграций и языков, сложная логика, расширенная поддержка
  запуска; цена от указанной, объём уточняется.
- Воркшоп «Сессия»: 2 часа онлайн, до 5 человек. «Команда»: до 12 человек,
  письменные выводы и карта возможностей.

Окончательные формулировки пишутся при реализации по этой схеме.

## 4. Проверки

- `scripts/check-shop-pages.mjs`, вызывается из `check-agent-paths`:
  для каждого товара есть `shop/<slug>.html` и вход в `vite.config.ts`;
  `meta aihub-product` совпадает с именем файла; нет лишних HTML в `shop/`;
  у товара ≥1 уровня, id уровней уникальны, `openEnded` только у самого
  дорогого; у каждого уровня есть тексты в `data.ts`.
- `node --test` (`backend/contact-api`): цена по `packageId`; неизвестный
  `packageId` → `VALIDATION_ERROR`; без `packageId` → самый дешёвый уровень;
  один товар с двумя разными уровнями даёт две строки; уровень в письме менеджеру.
- `npx tsc --noEmit -p tsconfig.shop.json` охватывает новые файлы;
  `tsconfig.design-system.json`; `npm run build`;
  `node scripts/check-agent-paths.mjs --dist dist`; `git diff --check`.
- `scripts/shop-smoke.mjs`: «Подробнее» на каждой из 8 карточек открывает
  нужную PDP с тем же языком; выбор уровня даёт нужную строку и сумму;
  старая корзина `[{id, qty}]` открывается без ошибки. Запуск с Playwright
  во временной папке, вне проекта.
- Вручную: EN/RU, 390/768/1200/1440 px, клавиатура, reduced motion,
  неизвестный slug.

| Критерий приёмки | Подтверждение |
| --- | --- |
| Карточки ведут на правильные PDP | `check-shop-pages` + smoke по 8 карточкам |
| Диапазоны соответствуют уровням | Диапазон вычисляется из уровней + `check-shop-pages` |
| Нет ложных обещаний | `priceNote` везде + сверка текстов человеком (пункт в PR) |

## Выпуск

Frontend и backend выкладываются вместе: формат заявки и каталога меняется.
Документация `docs/shop.md` и `docs/shop-backend-guide.md` обновляется в той же
ветке. До выкладки заказчик сверяет черновик уровней, цен и сроков.
