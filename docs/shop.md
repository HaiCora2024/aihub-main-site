# AIHUB: магазин готовых AI-решений

Реализованный контракт: [backend магазина](shop-backend-guide.md).
Настройка, хранение и выпуск: [эксплуатация](shop-operations.md).
Реализация локальная; production требует отдельного подтверждения.

Страница `/shop.html` перенесена из предоставленного `index (2).html` на
React 18 + TypeScript. Собирается тем же Vite, что лендинг, кейсы и каталог
дизайн-системы. Внешний HTML не загружается через iframe, старые inline-скрипты
и стили не исполняются. Дополнительные runtime-зависимости не установлены.

## Что перенесено

- Восемь продуктов, пять категорий; у каждого продукта уровни (`packages`) с ценами нетто в EUR.
- Отдельная страница каждого продукта `shop/<slug>.html`: уровни, состав, факторы цены, сроки.
- Поиск по названию/описанию, фильтрация категории и пустое состояние.
- Локальная корзина: добавление, изменение количества, удаление, итог, сохранение.
- Отдельная форма необязывающей заявки: контакты, billing ФЛ/B2B, VAT ID, условия.
- Добавлена полноценная русская локализация и параметр `?lang=ru`.
- Главная ведёт в магазин через `Shop / Магазин`; магазин ведёт на главную,
  кейсы, услуги, контактную форму и юридические страницы.

## Граница заявки

Исходный HTML содержал пустые `storeId`, `publicToken`, `demoWebhook` и поэтому
работал как локальная демонстрация. Теперь корзина ведёт в `checkout.html`.
Новый API сохраняет заявку и независимо ставит письма sales и клиенту в очередь.
Он не заключает договор, не принимает оплату, не рассчитывает VAT и не пишет в Sheets.
Без `VITE_SHOP_API_URL` и доступного каталога отправка закрыта, а не заменена демо.

Корзина хранится в `localStorage.aihub_cart` в формате `[{id, packageId, qty}]`.
Строка без `packageId` (старый формат) получает самый дешёвый уровень.
Неизвестные ID, уровни и неправильные значения удаляются, повторы объединяются,
количество ограничено 99 единицами на строку «продукт + уровень». Если хранилище недоступно,
корзина продолжает работать в памяти. Изменения синхронизируются между вкладками.
Персональные поля checkout хранятся только в React-состоянии. При перезагрузке
они теряются; ключ незавершённой отправки и неперсональный снимок корзины остаются
в sessionStorage для проверки статуса. Принятая заявка вычитается из свежей корзины,
а изменения другой вкладки сохраняются. Блокировка хранилища мешает переносу корзины
на другую страницу; она не создаёт ложного подтверждения.

Онлайн-оплата и автоматические счета потребуют отдельного этапа интеграции.
Не добавляйте секретные токены в `VITE_*`, браузерный код или Git.
Старый неактивный адаптер Ecwid не переносился как якобы рабочая платёжная система.

Имя, уровни, цены и единицу меняйте в общем `catalog.json`, одновременно повышая версию.
Карточка показывает диапазон от самого дешёвого до самого дорогого уровня; `openEnded`
допустим только у самого дорогого и добавляет «+» («от» на странице продукта).
Один уровень показывается одной ценой. Все цены подписаны `priceNote` (нетто, + VAT, ориентировочно).
Корзина, заявка и письма считают цену выбранного уровня.
Тексты уровней добавляйте в `product-content.ts` с теми же id, что в каталоге;
новому продукту нужен `shop/<slug>.html` и вход в `vite.config.ts`.
Несоответствия находит `node scripts/check-shop-pages.mjs`.
Описание и категорию меняйте в `data.ts`. Backend и frontend выпускаются согласованно.
Сохраняйте ID существующего продукта: это ключ сохранённой корзины.
Новый продукт должен иметь уникальный ID и иконку из `SolutionIconName`.
При расширении набора добавьте WebP и запись в `solutionIcons`.
Счётчик результатов доступен скринридеру, но не показан визуально. Иллюстрация Hero использует товары
с индексами 0, 1 и 4; при изменении состава коллекции обновите её в `Shop.tsx`.

Новый текст добавляется в обе ветки `copy.en` / `copy.ru`.
Новые категории добавляются в `categories` с типом `CategoryId`, названием EN/RU
и одним из акцентов UI-kit. Не меняйте глобальные стили лендинга ради магазина.

## Дизайн-система

Страница использует реальные `PageContainer`, `Section`, `SectionHeading`,
`Grid`, `SurfaceCard`, `Badge`, `Button`, `CtaFrame`, `TextField`, `NavLink`,
`Reveal` и `DecorativeGlow` из `src/design-system/`.
Цвета, шрифты и эффекты берутся из `--aihub-*`.

Контейнер фиксирован на 1140 px; десктоп начинается с 1200 px.
Сетка: одна колонка на телефонах, две от 768 px, три от 1200 px.
Смена ширины экрана не масштабирует весь десктопный макет.
Мобильные поля 16 px, планшетные 24 px. Декор не перехватывает клики,
внешняя оболочка обрезает только горизонтальное переполнение.
Карточки появляются последовательно; reduced motion отключает анимации.
CTA имеют единый hover UI-kit: подъём, scale 1.035, усиление свечения.

Иконки доступны также в `/design-system.html#icons`. Происхождение, точный prompt,
модель и SHA: [shop-icons.md](shop-icons.md).

## Сборка и локальный просмотр

Общие для лендинга и магазина `src/components/SiteHeader.tsx` и
`site-header.css` задают одно меню: услуги, кейсы, дорожная карта, команда,
магазин, язык и консультация. На телефонах есть раскрываемое меню с Escape
и клавиатурным фокусом. В футере лендинга добавлен второй переход в магазин.
Логотип с яйцом и рамка CTA хранятся локально в `public/brand/`.
Язык передаётся через `?lang=ru|en`, включая переходы к секциям главной.

`src/components/TypewriterText.tsx` используется обоими hero. Скорость 55 ms,
старт через 400 ms, мигающий курсор. Высота текста резервируется заранее;
скринридер получает сразу полный заголовок. Reduced motion отключает печатание.
Заголовок магазина приведён к лендингу: Geologica 700, uppercase, 86 px desktop,
32/48/64 px на меньших ширинах. Промежуток до каталога сокращён примерно до 40 px.
Дополнительная проверка: `scripts/site-navigation-smoke.mjs`.

```bash
npm ci
npx tsc --noEmit -p tsconfig.shop.json
npm run build
npm run preview -- --port 4173 --strictPort
```

Открыть `http://localhost:4173/shop.html` или
`http://localhost:4173/shop.html?lang=ru`.
Страница включена в `build.rollupOptions.input` файла `vite.config.ts`.
Все внутренние пути и иконки учитывают `import.meta.env.BASE_URL`.
Для GitHub Pages не нужен дополнительный сервер или отдельный workflow.
Публикация выполняется только по явному запросу. Push в `main` запускает существующий
Pages workflow; отдельный backend этим workflow не разворачивается.

## Проверка в браузере

Playwright можно установить отдельно от проекта:

```bash
npm install --prefix /tmp/aihub-shop-qa-tools playwright
PLAYWRIGHT_MODULE=/tmp/aihub-shop-qa-tools/node_modules/playwright/index.mjs \
CHROME_PATH=/absolute/path/to/chrome \
node scripts/shop-smoke.mjs
```

`PREVIEW_URL` задаёт базовый URL с завершающим `/`, `QA_OUTPUT` — папку отчёта.
Проверяются обе локали на 390/768/1199/1200/1440/1920 px, поиск, фильтры,
иконки, арифметика корзины, перезагрузка, невалидное хранилище, модальные окна,
клавиатура, reduced motion, отсутствие сетевой отправки и переходы с главной.
Не используйте этот тест как проверку реального платёжного процесса.

Результаты последней проверки: [shop-qa.md](shop-qa.md).
Сценарии заявок и юридических страниц: `scripts/checkout-smoke.mjs` и
[регламент проверок выпуска](shop-operations.md). Этот тест поднимает временные
локальные SQLite/API/Vite/SMTP sink и никогда не доставляет реальные письма.

Общий `tsconfig.app.json` до этого изменения содержал шесть ошибок в старых
страницах Cases. Изолированная проверка `tsconfig.shop.json` позволяет отделить
их от магазина и UI-kit; наличие старых ошибок не скрывается общим `skip`.
