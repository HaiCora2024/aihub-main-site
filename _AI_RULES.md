# Правила разработки AIHUB

Актуальная точка входа: [AGENTS.md](AGENTS.md).
Пошаговая работа: [гайд по страницам](docs/agent-page-guide.md).
Этот файл сохранён как совместимый вход для агентов, читавших прежние правила.

## Реальная архитектура

- Компоненты нового UI-kit: [src/design-system/components.tsx](src/design-system/components.tsx).
- Общая навигация: [src/components/SiteHeader.tsx](src/components/SiteHeader.tsx).
- Композиции и демонстрационные шаблоны: [src/design-system/patterns.tsx](src/design-system/patterns.tsx).
- Контент магазина: [src/shop/data.ts](src/shop/data.ts).
- Сборка отдельных страниц: [vite.config.ts](vite.config.ts).

Прежний документ описывал предполагаемые, но не реализованные каталоги
`src/components/ui/`, `src/components/blocks/`, `src/layouts/`, `src/data/schemas/`
и PageBuilder. Не создавать их автоматически. `clsx`/`classnames` не являются
обязательными зависимостями; экспорт и именование сохранять по месту изменения.

## Правила кода

1. Использовать строгую типизацию и union types для вариантов. Входные данные
   сервера считать `unknown` до runtime-валидации, не маскировать их через `any`.
2. Переиспользовать UI-kit и `--aihub-*`. Стили новой страницы ограничивать её
   классом; не менять legacy Tailwind-токены ради нового экрана.
3. Не переписывать существующие arbitrary Tailwind values попутно. В новых
   UI-kit страницах предпочтителен scoped CSS; размеры и цвета берутся из токенов.
4. Контент, преобразования данных и сетевой слой отделять от представления.
5. Не делать интерактивные div вместо ссылок и кнопок. Не рендерить недоверенный HTML.
6. Сохранять адаптивность, RU/EN, состояние ошибок, клавиатуру и reduced motion.
7. Не выдавать демонстрационные формы, метрики и checkout за production-функции.

Проверки, работа с грязным деревом и разрешения на публикацию определены в
[AGENTS.md](AGENTS.md), а не в исторических заметках отдельных блоков.
